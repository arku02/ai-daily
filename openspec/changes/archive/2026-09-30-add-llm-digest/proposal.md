# 變更提案

## Why
第 1 步每天產生約 250 筆原始候選（data/raw/<日期>.json），但使用者要的是約 20 分鐘讀完、每則附「摘要／重點／你可以怎麼用／來源」的繁體中文早報。2026-09-30 使用者確認手動範例的深度與「你可以怎麼用」的方向都正確（回饋 1A、2A），並要求「今天試一個」優先挑容易上手的項目。使用者希望以免費為主，已建立 Gemini 免費方案的 API key（專案 ai-daily，Free tier）。

成功標準：一個指令把當天原始資料變成結構化的早報內容，章節、欄位和範例一致；來源連結一定是真實抓到的網址；每天的 API 呼叫次數少到免費額度用不完；單則寫作失敗時仍然產出其餘內容。

## What Changes
新增 `python -m ai_daily digest`：
- 候選準備：每個來源依熱度取前 N 筆，壓縮成精簡清單。
- 選題：一次 LLM 呼叫，依使用者背景選出四個章節的項目、「今天只看三件事」與「今天試一個」，並排除融資與人事新聞。
- 補充內容：替入選項目抓 README 或網頁內文片段，讓摘要有東西可依據。
- 寫作：依章節分批呼叫 LLM，寫出摘要、重點、你可以怎麼用；來源連結由程式從原始資料帶入。
- 使用者背景放在 profile 設定檔，實際檔案不進版控，repo 裡只放範例。
- 輸出 `data/digest/<日期>.json`，供第 3 步產生網頁與 Telegram 訊息。

採 full 模式：新增外部 API 依賴與新的資料格式。

## Non-goals
- 產生 HTML 網頁、Telegram 推送、回饋按鈕與回饋 repo（第 3 步）。
- 依回饋調整排序（有回饋資料後再做）。
- GitHub Actions 排程（第 4 步）。
- 使用付費模型或 Google Search grounding（免費方案不提供）。

## Capabilities
### New Capabilities
- llm-digest: 把每日原始候選轉成有章節、摘要、應用建議與真實來源連結的結構化早報內容。
### Modified Capabilities
- 無。source-fetch 的輸出格式不變，本變更只讀取它。

## Impact
新增 `ai_daily/digest/`（候選、選題、補充、寫作、LLM 客戶端）、`digest.toml`、`profile.example.toml`、`data/digest/` 輸出與測試。仍只用標準函式庫。依賴 Gemini API 免費方案：免費方案的輸入可能被 Google 用於改進產品，但送出的都是公開資料與使用者自訂的背景描述；確切的每日上限只能在 AI Studio 查看，設計以低呼叫次數與模型備援降低風險。LLM 可能寫錯內容，以「只能依據提供的資料」的指示、連結由程式帶入、格式驗證來降低影響，無法完全消除。
